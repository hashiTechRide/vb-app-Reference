全対象を追跡し、モード別分岐の影響範囲を可視化するスクリプトを作ります。特に文字列リテラルによる分岐制御の追跡が肝です。

影響範囲解析スクリプトです。

**使い方：**

```powershell
# ① 対象指定モード: 特定のオブジェクトの影響を調査
.\vbnet_impact.ps1 -Path "C:\Projects\App" -Target "g_FuncMode","btnConfirm","入庫検品","CheckZaiko"

# ② 全体スキャンモード: 全オブジェクトを自動検出して網羅的に一覧化
.\vbnet_impact.ps1 -Path "C:\Projects\App"

# ③ モード変数を明示指定（自動検出がうまくいかない場合）
.\vbnet_impact.ps1 -Path "C:\Projects\App" -ModeVar "g_FuncMode","strKinou"
```

**出力される5シート：**

| シート | 内容 |
|---|---|
| **①影響範囲一覧** | 全参照箇所を行単位で一覧。「どのファイルの何行目で、どのメソッド内で、どのモード分岐の中で参照されているか」が分かる。書込=赤, モード変数=黄, 分岐キー文字列=橙 |
| **②対象別サマリー** | オブジェクトごとに参照ファイル数・モード数・書込数を集計し、影響度スコアで降順ソート。「このオブジェクトを変えたら何箇所に影響するか」が一目で分かる |
| **③モード横断マトリクス** | 行=オブジェクト, 列=モードコンテキスト。○=参照, ●=書込。**ある機能だけ変えたいのに他の機能モードでも●が付いているオブジェクトが要注意** |
| **④分岐キー文字列** | `"入庫検品"`, `"出庫ピッキング"` 等の文字列リテラルが Case文/If文でどこで使われているかを全箇所列挙 |
| **⑤変更チェックリスト** | チェック欄付きの変更前確認リスト。「3モードで参照、5ファイルに分散、書込2箇所 → 全モードテスト必要」等の注意点を自動生成 |

**核心機能 — モードコンテキスト追跡：**

各参照箇所について「その行がどのモード分岐の中にあるか」を自動判定します。例えば：

```
Select Case g_FuncMode
    Case 1          ← モードコンテキスト = "1"
        lblTitle.Text = "入庫検品"    ← この行は「Case 1」の中
    Case 2          ← モードコンテキスト = "2"  
        lblTitle.Text = "出庫ピッキング"
End Select
```

これにより「`lblTitle` を変更したいが、Case 1 だけでなく Case 2 でも参照されている」ことが③のマトリクスで一目で分かります。
